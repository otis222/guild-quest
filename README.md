# 公會委託單

把基礎課作業拆成 10 分鐘的「任務」，每完成一個，就點亮自己 OC 設定卡的一片；交件時，作業照片會變成 OC 的一部分，也會放上公會大廳的展台。

- **網址**：https://otis222.github.io/guild-quest/
- **版本**：v1.0（2026-10-11）

TAICA「生成式 AI：文字與圖像生成的原理與實務」第五週作業〈用 Vibe Coding 做出一個互動網頁〉。
作品延伸自我在大同大學「數位創作與整合」課的分組專題（[otis222/oc-guild-quest](https://github.com/otis222/oc-guild-quest)）：先和 AI 把想法整理成規格，再用 Claude Code 照規格一張一張任務卡實作。這個 repo 放的是整理成單一 `index.html` 的作業版。

## 規格書（Specification）

這份規格書是我把想法和企劃交給 AI（Claude），由 AI 整理、補齊成完整規格，再由我確認後定稿。實作時，AI（Claude Code）每次開工前都會先讀企劃表，也就是這份規格的來源。

### 一、基本資訊

- **給誰用**：為了畫角色而來，但基礎課作業總是拖到最後一晚的設計系新生。
- **痛點**：訪談一位大一同學。簡單的作業當場寫完，剩下的拖到最後一晚；畫角色是她的舒壓方式；她不知道平面課跟角色美術有什麼關係。
- **要解決的事**：讓她做基礎課作業時，也覺得自己在往角色美術前進。
- **檔案**：單一 HTML 檔（`index.html`），CSS 和 JavaScript 都寫在裡面；小人圖片放在同一層的 `sprites/` 資料夾，用相對路徑讀取。放上 GitHub Pages 就能用手機或電腦打開。
- **裝置**：手機直式（375×812）優先，桌機也能用。
- **資料**：不用帳號、不用登入。OC、委託進度和作業照片只存在自己的瀏覽器（IndexedDB），不會上傳。
- **名稱**：大廳沿用已經做好的「OC 巡展廣場」3D demo，所以左上角和招牌上還是這個名字。

### 二、畫面與流程

1. **冒險者登記**：第一次打開時出現。輸入名字（最多 12 字）→ 從 10 位 AI 小人選一位，或上傳自己畫的 OC（PNG／JPG，白底會自動去背）→ 按「加入公會」。
2. **公會大廳**：3D 廣場。自己的 OC 腳下有粉紅光圈，鏡頭跟著它；點地板讓它走過去，WASD／方向鍵也能走；拖曳轉鏡頭，雙指或滾輪縮放。另外 6 位「公會成員」會自己閒逛、互相打招呼，點它會跳一下、說一句話。右上角有「跟夥伴打招呼」「等到黃昏」；招牌旁的徽章是公會等級。
3. **接委託**：點大廳裡的委託板，或按下方「委託板」→「接新委託」→ 填委託單：選課程（字體設計／色彩學／平面構成／手繪基礎，也可以「＋ 新課程」自己加）→ 作業名稱 → 期限（預設 7 天後 23:59）→ 公會自動拆成 5 個任務（每個 10 分鐘）和最後的交件 → 按「接下委託」。任務可以改名、調整順序、刪掉，也可以再加一個。
4. **開始任務**：委託卡上寫課程、作業名稱、截止倒數和進度。按「開始任務（10 分鐘）」→ 大字倒數，可以「休息一下」「提早完成」「再 5 分鐘」，也可以「回大廳」讓時間繼續跑。OC 會走到委託板前工作，頭上有進度環。時間到會問「這個任務完成了嗎？」→「完成了」或「再 5 分鐘」。
5. **設定卡亮一片**：完成任務後，OC 跳一下說「任務完成！」，大廳下方浮出小提示「設定卡亮了一片」和「色彩學・色相環　1/5」，按「看 OC 設定卡」就看得到剛亮的那一片。
6. **交件**：5 個任務都完成後，委託卡上的按鈕變成「交件」→「拍照」或「從相簿選」→ 依課程預覽成果（色彩學：從照片抽出的 OC 新配色；字體設計：拖曳框框框出名牌；平面構成、手繪基礎：放進設定卡的版面、草稿）→ 按「交件」。OC 說「交件了！」，照片放上大廳的展台（點相框可以放大看），公會等級＋1。
7. **OC 設定卡**：上面是 OC、公會等級、完成度和「換造型」；接著是 OC 目前的部件（名牌／配色／版面／草稿）；下面每門課一區、每區 3 個圓形格子。一格是一張委託，每完成一個任務亮一片；點任何一片，會寫出是哪一天、哪門課的哪個任務，例如「10/11 色彩學・讀要求選主題（色相環）」。

### 三、規則

- 一個任務 10 分鐘；一張委託預設 5 個任務加交件（可以改成 1～10 個任務）。完成一個任務剛好亮一片，同一個任務不會亮兩次。
- 同時只跑一個任務；開始另一個時，原本那個自動暫停。
- 倒數用開始的時間點來算：重新整理或關掉分頁再回來，剩下的時間還是對的。時間到以後放著不按，不算專注時間。
- 過了期限的委託顯示「已逾期」，不會被刪掉。
- 同一門課的第 4 張委託回到第 1 格，舊的收進「歷史」；完成度把歷史也算進去。
- 每門課交件後解鎖 OC 的一個部件：字體設計→名牌（換掉頭上的名字）、色彩學→配色（換掉腳下光圈的顏色）、平面構成→版面、手繪基礎→草稿；自己加的課程在建立時選一種。
- 公會等級＝1＋已交件的委託數。展台最多放 5 張照片，再交件就換掉最舊的。
- 不做帳號、排行榜、設定頁；網頁裡不呼叫任何 AI 服務（小人圖是事先用 ComfyUI 生成好的）。
- 研究用的事件紀錄和匯出只在網址加 `?research=1` 時出現，一般網址看不到入口。

### 四、視覺與風格設定（Visual Style）

- **整體風格**：淡彩卡通 3D 廣場（卡通著色）配上圓角半透明面板，像遊戲裡的公會大廳。按鈕和提示用公會冒險者的口吻，句子短、不用驚嘆號轟炸。
- **配色**：文字深紫 `#2f2542`、次要文字 `#6b5f80`；主色粉紅 `#ff6f97`（主要按鈕、主角光圈、焦點框）、淡粉 `#ffe1ea`；背景天空藍 `#cfe6ff`；面板是 78% 不透明的白色加毛玻璃（模糊 10px）。
- **課程顏色**：字體設計 `#b49bff`、色彩學 `#ff8fae`、平面構成 `#7fb6ff`、手繪基礎 `#7fd48f`；自己加的課程依序用橘 `#ffad66`、青綠 `#56cfc3` 等 6 色輪流。
- **字體**：Noto Sans TC（蘋果裝置用 PingFang TC，Windows 用微軟正黑體）。
- **動態**：小人走路時上下彈跳、壓扁拉伸、左右翻轉；設定卡點亮動畫 0.7 秒；展品相框輕輕上下浮動；「等到黃昏」時天色漸變。系統設定「減少動態效果」時不播點亮動畫。

### 五、佈局與結構（Layout & Structure - Mobile First）

- 以手機直式 375×812 為基準，畫面不會左右捲動；桌機的對話框置中，最寬 420px。
- **上方**：左邊是標題面板，右邊是「跟夥伴打招呼」「等到黃昏」。
- **中間**：整個畫面是 3D 大廳，Three.js 畫場景、PixiJS 畫小人，兩個共用同一個 WebGL 畫布。
- **下方**：「委託板」「OC 設定卡」兩顆按鈕；完成任務的小提示浮在按鈕上方，6 秒後自己收起來。
- **對話框**（委託板、填委託單、OC 設定卡、交件）：卡片置中，按 Esc 或 ✕ 關閉，一次只開一個。
- **計時畫面**：上面是任務名稱和大字倒數，下面是操作按鈕，中間透明，看得到 OC 在委託板前工作。

### 六、技術規格

- 程式用 TypeScript 寫、Vite 打包，再把全部 JavaScript 和 CSS 內嵌進 `index.html`；Three.js 0.170、PixiJS 8.13 也包在裡面，不從外部網址載入。需要支援 WebGL2 的瀏覽器，不支援時顯示一句說明，不會白畫面。
- **存檔**：IndexedDB；存檔有版本號，舊存檔讀進來會自動升級；照片另外存，存檔裡只放照片的編號。
- **計時**：用開始時間和累計暫停時間計算；計時中請瀏覽器保持螢幕不變暗，Android 時間到會震動。
- **照片**：在瀏覽器裡縮成長邊 1024px、JPEG 品質 0.85 才存；配色用中位切割法抽出最多 5 色。
- **效能**：像素比最多 2；連續 3 秒低於 40 FPS 時自動關陰影、降低解析度。
- **品質**：187 個單元測試；每一階段完成後都用 375×812 實際操作驗收。

## 修改過程分享

1. **規格是怎麼跟 AI 討論出來的**：每做完一個階段，AI 會把它猜不到、只有我們能決定的事列成「需要人確認的」，我和組員回答後才往下做。例如：
   - AI 問：「OC 建好以後不能換圖，要不要讓設定卡可以換？」→ 決定：可以，加「換造型」。
   - AI 問：「完成任務後設定卡會自動跳出來，會不會太打擾？」→ 決定：改成大廳的小提示。
   - AI 問：「同一門課接第 4 張委託時，完成度會往下掉，要不要把歷史算進去？」→ 決定：算進去。
   - AI 問：「時間到以後放著不按的時間，先不算專注時間，可以嗎？」→ 決定：可以。
2. **做出來以後發現的問題，再請 AI 修正**：
   - 在名字欄打字時，W、A、S、D 會被拿去走路 → 在輸入框裡打字不再觸發走路。
   - 主角出生在廣場邊緣，手機上靠在畫面邊邊 → 改從噴水池前出現。
   - 任務清單在 375 寬會撐破卡片 → 欄寬改成可以縮。
   - 展品從最左邊開始放，手機直式看不到第 1 張 → 改從中間的展台開始放。
   - 正式網址上，研究面板按下去 26 秒才出現 → 改成一打開網頁就先載入。
3. **為了符合這份作業再修改**：原本是 Vite＋TypeScript 的多檔專案，不符合「單一 index.html」→ 多一個打包步驟，把 JS、CSS 全部塞進 `index.html`。作業網址和組專案網址在同一個網域，存檔會互相讀到 → 作業版的資料庫改名。

## 從組專案打包成單一 index.html（tools/）

`tools/` 裡是打包用的腳本，網頁本身不會用到。它們把組專案整理成這份作業要的格式，組專案本身的檔案不用改：

1. 取組專案某個 commit 的原始碼，執行 `npm ci`。
2. `tools/build-hw5.sh <原始碼資料夾> <輸出資料夾>`：先跑型別檢查和單元測試 → 用 `tools/vite.hw5.config.mjs` 把程式打成一個 JS → `tools/inline.mjs` 把 JS、CSS 塞進 `index.html` → 圖片留在 `sprites/`。
3. `tools/check-loop.mjs <網址> <截圖資料夾> <交件用的照片>`：用無頭 Chromium 以 375×812 從冒險者登記玩到交件、重新整理，每一步截圖，並檢查存檔、錯誤和對外的網路請求。`tools/check.mjs` 是只走到大廳的簡短版。
